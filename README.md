# oiltrack - трекер капель масла для опыта Милликена

Программа берёт видео из окуляра установки Милликена и делает работу, которую обычно делают глазами с секундомером:

1. находит капли на каждом кадре;
2. связывает их в трекиЖ отслеживает каждую каплю, в том числе через моменты включения и выключения поля;
3. сама определяет, когда переключали поле, и находит перезарядки капель;
4. считает скорости капли с полем и без поля, а по ним её заряд;
5. по всем каплям строит гистограмму зарядов, на которой должна проявиться кратность заряду электрона.

Результат CSV-таблицы, графики и проверочное видео, на котором видно, что именно нашла программа.

```bash
python -m venv venv

```

## Быстрый старт

```bash
# 1. Положите видео в media/ и укажите напряжение для этого видео
oiltrack run media/IMG_6823.MOV -c config.yaml --set charge.voltage_V=500

# 2. Смотрите результат
ls output/IMG_6823/
```

В конце прогона программа печатает сводку: что нашлось, сколько треков, сколько капель с зарядом и сколько времени занял каждый этап. Первый прогон видео длиной в пару минут занимает несколько минут. После прогонки результат кешируется.

**Что посмотреть первым делом:**

- `review.mp4` - исходное видео с нарисованными треками.
- `plots/field_switches.png` - найденные моменты переключения поля. Сверьте их с реальностью.
- `charges_hist.png` - гистограмма зарядов.

## Команды

| Команда | Что делает |
|---|---|
| `oiltrack run VIDEO -c config.yaml` | Весь пайплайн от видео до зарядов |
| `oiltrack detect VIDEO -c config.yaml` | Только маска поля зрения, фон и детекции капель (результат сохраняется в кэш) |
| `oiltrack switches VIDEO -c config.yaml` | Только моменты переключения поля: из конфига, найденные автоматически и уточнённые |
| `oiltrack review VIDEO -c config.yaml` | Перерисовать `review.mp4` и графики по уже готовым трекам |
| `oiltrack charges DIR [DIR ...]` | Пересчитать заряды по готовым папкам `output/<видео>/` - по одной или по нескольким вместе |
| `oiltrack batch videos.yaml` | Обработать серию видео, у каждого свои параметры, и построить общую гистограмму |
| `oiltrack synth OUT.mp4` | Сгенерировать синтетическое видео с известными треками (для проверки программы) |

### Общие опции для `run`, `detect`, `switches`, `review`

| Опция | Смысл |
|---|---|
| `-c config.yaml` | Конфиг. Поддерживает наслаивание. |
| `--set КЛЮЧ=ЗНАЧЕНИЕ` | Поменять один параметр, не трогая файл. Например `--set charge.voltage_V=700` или `--set field.switches_s=[12.4,31.0]` |
| `-o DIR` | Корневая папка вывода (по умолчанию `output/`) |
| `--t-start С`, `--t-end С` | Обработать только кусок видео, в секундах |
| `--no-cache` | Пересчитать всё с нуля |
| `-q` | Меньше сообщений в консоли |

Только для `run`:

- `--no-review` - не рисовать видео и графики. Это заметно быстрее, удобно, когда подбираете параметры.
- `--mode stop|split` - что делать при перезарядке капли (см. `segment.mode` ниже).

Для `charges`: `-o DIR` - куда писать результат, `--off-state A` - явно указать, какой режим считать «поле выключено», `--set` - поменять константы для всех папок сразу.

Для `batch`: `--only-charges` - не прогонять видео заново, только пересчитать заряды; `--review` / `--no-review` - перекрыть значение `review:` из манифеста.

Для `synth`: `--seed`, `--n-drops` (число капель), `--duration` (длительность, с), `--switches 6.0 12.0` (моменты переключения поля).

## Типичные сценарии

### Одно видео

```bash
oiltrack run media/500_1.mov -c config.yaml --set charge.voltage_V=500
```

### Моменты переключения известны из протокола

Автоматический поиск обычно ошибается не больше чем на 1-2 кадра. Если моменты всё-таки записаны в протоколе, можно задать их явно - программа только уточнит их до кадра:

```bash
oiltrack run media/700_1.mov -c config.yaml \
    --set charge.voltage_V=700 \
    --set field.switches_s=[12.4,31.0,55.2] \
    --set field.states=[off,on,off,on]
```

Проверить, что нашла программа, не запуская весь пайплайн:

```bash
oiltrack switches media/700_1.mov -c config.yaml
```

### Серия видео с разным напряжением

Скопируйте `videos.example.yaml` в `videos.yaml` и впишите свои видео:

```yaml
config: config.yaml
out: output
charges_out: output/charges_all
review: false

set:                              # общее для всех видео
  charge:
    reference_voltage_V: 500      # к какому U приводить заряды на общей гистограмме

videos:
  - path: media/500_1.mov
    set:
      charge: {voltage_V: 500}
  - path: media/700_1.mov
    set:
      charge: {voltage_V: 700}
      t_end: 60                   # только первые 60 с
```

```bash
oiltrack batch videos.yaml
```

Каждое видео получит свою папку `output/<имя>/` со своими зарядами, а общая гистограмма по всем видео окажется в `output/charges_all/`. Чтобы её корректно склеивать, заряды из видео с разным напряжением приводятся к одному `reference_voltage_V`.

Если поменяли только физические константы (плотность масла, зазор между пластинами), видео прогонять заново не нужно:

```bash
oiltrack batch videos.yaml --only-charges
# или по отдельным папкам:
oiltrack charges output/500_1 output/700_1 --set charge.rho_oil_kg_m3=875
```

## Настройка: `config.yaml`

Все параметры живут в `config.yaml`, у каждого есть комментарий. Любой параметр можно не указывать - тогда возьмётся значение по умолчанию из `src/config.py`. Для обычной работы достаточно трёх групп.

**Константы установки** (секция `charge`) - от них зависит абсолютный заряд:

| Параметр | Что это |
|---|---|
| `plate_gap_m` | Расстояние между пластинами конденсатора, м |
| `voltage_V` | Напряжение на пластинах, В. Обычно своё у каждого видео, поэтому задаётся через `--set` или в `videos.yaml`, а не здесь |
| `rho_oil_kg_m3` | Плотность масла |
| `eta_air_Pa_s`, `rho_air_kg_m3`, `pressure_Pa` | Воздух: вязкость, плотность, давление |
| `cunningham_b_Pa_m` | Поправка Каннингема для мелких капель; `null` - без неё |

**Масштаб** (секция `calibration`):

- `mm_per_division` - цена деления шкалы окуляра в мм. Шаг и угол наклона шкалы на видео программа находит сама; эта цифра нужна, чтобы перевести деления в миллиметры.
- `z_sign` - куда смотрит «вверх». Окуляр переворачивает изображение, поэтому по умолчанию `+1`: z растёт вниз по кадру.

**Поле** (секция `field`):

- `switches_s` - моменты переключения в секундах, или `null` для автоматического поиска.
- `states` - подписи режимов по порядку, например `[off, on, off, on]`. По умолчанию `A, B, A, B`. Какой из режимов «поле выключено», программа определит сама: это режим с самым узким разбросом скоростей.

**Что делать при перезарядке капли** (`segment.mode`):

- `stop` - трек капли обрывается на первой перезарядке (по умолчанию);
- `split` - трек продолжается, а после перезарядки начинается новый участок с новым `segment_id`.

Остальные секции - `roi`, `background`, `detect`, `link`, `quality` - это пороги детекции и трекинга. Их стоит трогать, только если `review.mp4` показывает, что капли теряются или путаются.

Если без всего перечисленного программа не может посчитать абсолютный заряд, она всё равно считает **относительный** `q_rel`. По нему гистограмма тоже показывает кратность, только без перевода в кулоны.

## Что получается на выходе

Всё, что относится к одному видео, лежит в `output/<имя_видео>/`. Все CSV в UTF-8, разделитель - запятая, десятичная точка.

| Файл | Содержимое |
|---|---|
| `summary.json` | Сводка прогона: калибровка, переключения, число треков, время этапов |
| `tracks.csv` | Каждая капля на каждом кадре: координаты (px, деления, мм), радиус, яркость, тип (точка/кольцо), флаги |
| `segments.csv` | Участки треков между событиями: скорость `v_z` с погрешностью, коэффициент диффузии, режим поля, причина конца участка, качество |
| `pairs.csv` | Пары «участок до переключения / участок после» одной и той же капли без перезарядки между ними - из них считается заряд |
| `field_switches.csv` | Моменты переключения поля (время и кадр) и откуда они взяты |
| `velocity_stats.csv`, `switch_series.csv` | Промежуточные ряды, по которым искались переключения |
| `charges.csv` | Заряд каждой капли: `q_rel`, приведённый `q_rel_norm`, а если заданы константы - `q_C` и `q_over_e`, все с погрешностями |
| `charge_pairs.csv` | Заряд по каждой паре по отдельности (одна капля может дать несколько пар) |
| `charges_hist.png` | Гистограмма зарядов |
| `charge_settings.json` | С какими константами считались заряды (нужно для `charges` и `batch --only-charges`) |
| `particles/` | Отдельный CSV на каждую каплю (только для треков не короче `quality.min_track_s`) |
| `plots/` | `particle_XXXX.png` - z(t) для каждой капли, `v_z_histogram.png`, `field_switches.png` |
| `review.mp4` | Видео с наложенными треками |
| `cache/` | Кэш этапов, можно удалить в любой момент |

### Как читать `segments.csv`

- `end_reason` - почему закончился участок: `field_switch` (переключили поле), `charge_change` (капля перезарядилась), `edge` (ушла за край поля зрения) или конец трека.
- `quality` - `ok`, если участок годный. Иначе там перечислены проблемы: `short` (слишком короткий), `defocus` (капля уходит из фокуса - радиус заметно вырос), `edge` (у края поля), `merge_risk` (рядом другая капля, могли перепутаться).

По умолчанию в расчёт заряда идут только пары, где оба участка `ok` и длиннее 2 с (`charge.require_ok`, `charge.min_segment_s`).

### Знак заряда

`q_rel > 0` - электрическая сила направлена вверх: в поле капля поднимается или падает медленнее, чем без поля. `q_rel < 0` - поле тянет вниз. Незаряженная капля даёт `q ≈ 0`.

## Как это работает (коротко)

1. **Поле зрения** (`roi.py`): по медиане кадров находится круг окуляра, всё вне круга отбрасывается.
2. **Фон** (`background.py`): скользящий перцентиль по времени. Капли движутся, шкала стоит, поэтому после вычитания фона остаются только капли.
3. **Детекция** (`detect.py`): капли в фокусе выглядят как точки, не в фокусе - как кольца. Точки ищутся фильтром LoG на нескольких масштабах, кольца - отдельным кольцевым фильтром. Работает параллельно на всех ядрах.
4. **Калибровка** (`calibration.py`): по автокорреляции находятся угол и шаг шкалы. Ось z строится перпендикулярно линиям шкалы, поэтому наклон камеры не важен. Скорости считаются в делениях шкалы в секунду - тогда видео, снятые с разного расстояния, сравнимы между собой.
5. **Переключения поля** (`field_switch.py`, `changepoint.py`): ищутся моменты, когда у многих капель одновременно скачком меняется скорость; затем уточняются до кадра.
6. **Треки** (`link.py`): детекции соседних кадров связываются в треки с учётом броуновского движения. Обрывки склеиваются, если капля ненадолго пропала под линией шкалы.
7. **Нарезка** (`segment.py`): трек режется на участки по переключениям поля и по изломам скорости - перезарядкам.
8. **Качество** (`quality.py`): участки помечаются флагами.
9. **Заряды** (`charges.py`): из пары «поле выключено / поле включено» одной капли считается заряд по закону Стокса. Пара всегда состоит из двух участков одного и того же трека, поэтому капли не перепутываются.

Формула: при скорости оседания $v_1$ без поля и скорости $v_2$ в поле (положительная - вверх)

$$
q = 9\pi\,\frac{d}{U}\,\sqrt{\frac{2\eta^3}{\Delta\rho\, g}}\;\sqrt{v_1}\,(v_1 + v_2),
$$

где $d$ - зазор между пластинами, $U$ - напряжение, $\eta$ - вязкость воздуха, $\Delta\rho$ - разность плотностей масла и воздуха. Всё, кроме скоростей, одинаково для всех капель одной установки, поэтому $q_\text{rel} = \sqrt{v_1}\,(v_1 + v_2)$ пропорционален заряду.

## Кэш

Каждый этап сохраняет результат в `output/<видео>/cache/`. Ключ кэша зависит от видео (имя, размер, время изменения), выбранного куска и тех параметров конфига, от которых этап зависит. Если поменять, например, порог в `link`, пересчитаются только трекинг и всё после него, а дорогая детекция возьмётся из кэша.

Если кажется, что результат «застрял», запустите с `--no-cache` или удалите папку `cache/`.

## Тесты

```bash
python -m pytest                    # все тесты, включая медленный сквозной (~1 мин)
python tests/run_tests.py           # быстрые тесты, медленный пропускается
python tests/run_tests.py --slow    # все
python tests/run_tests.py -k link   # только тесты, в имени которых есть «link»
```

Тесты прогоняют программу на синтетических данных с известным ответом. Они проверяют, что детекция находит больше 95% капель с ошибкой центра меньше 0,3 px, что ID капель не путаются при переключении поля, что переключения находятся с точностью ±2 кадра, что заряды считаются по формуле. Сквозной тест `test_pipeline_synth` рендерит синтетическое видео и прогоняет весь пайплайн.

Синтетическое видео можно сделать и вручную - например, чтобы посмотреть, как программа справляется:

```bash
oiltrack synth media/synth.mp4 --duration 20 --switches 6 12
oiltrack run media/synth.mp4 -c config.yaml
```

Рядом с видео сохраняется ground truth: `synth_gt.csv` с истинными положениями капель и файл с событиями (переключения, перезарядки), с которыми можно сравнить результат.

## Возможная проблема с самописными скриптами

**Свой скрипт, вызывающий пайплайн, падает с `RuntimeError` про bootstrapping** - детекция запускает процессы через `spawn`, поэтому код скрипта должен быть под `if __name__ == "__main__":`.

```
videos.example.yaml    пример манифеста для batch
make_slides_figures.py картинки для слайдов
src/
  cli.py               командная строка, пайплайн, кэш
  config.py            параметры и значения по умолчанию
  io_video.py          чтение видео и временных меток кадров
  roi.py               маска поля зрения
  background.py        вычитание фона
  detect.py            детекция капель
  calibration.py       угол и шаг шкалы, масштаб
  changepoint.py       поиск точек излома (PELT)
  field_switch.py      моменты переключения поля
  link.py              связывание детекций в треки
  segment.py           нарезка треков на участки, перезарядки
  quality.py           флаги качества
  export.py            запись CSV
  charges.py           заряды и гистограмма
  review.py            графики и review.mp4
  synth.py             синтетические данные
tests/                 тесты на синтетике
media/                 видео (в git не хранятся)
output/<видео>/        результаты
```
